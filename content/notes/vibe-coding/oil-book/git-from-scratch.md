刚把首页改顺眼时就可以提交，下一步再试菜单。做了一大堆才保存，出了问题容易忘记哪一步起了作用。

## 提交前先看差异

先用 `git status --short` 看文件，再用 `git diff` 看具体改动。提交说明写这一步解决了什么，比如「手机上收起侧栏」。未完成的想法留在自己的工作分支。

已经共享的提交需要撤销时，可以用 `git revert` 加一条回退记录。开 PR 时附启动和验收命令，让人能打开同一页面检查。
